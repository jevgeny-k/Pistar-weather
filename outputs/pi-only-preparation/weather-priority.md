# Whole-bulletin weather priority

This opt-in mode supersedes the November 9 traffic-priority experiment on the inspected target, at the operator's request. Source default remains off. Enable `--weather-priority` or `PISTAR_WEATHER_PRIORITY=1`; set `PISTAR_WEATHER_SERIALIZE_SLOTS=0` to replace the earlier yield-to-TS2 behavior.

After all parts have passed encode/decode validation, `play.py` reserves the entire bulletin with `begin_bulletin`. Existing network calls can finish; new network DMR streams on both slots are skipped. Weather begins after the 12-second quiet guard. The reservation remains in force across inter-part gaps, so a new TS2 call cannot truncate the space-weather section. Authentication and network control packets still pass. Actual RF transmissions cannot be physically prevented by this software; they no longer cancel an active weather part, but can delay the next part's quiet guard.

A skipped call stays skipped through its terminator, even if weather finishes first. Its trailing audio is not resumed. Stream tracking is bounded to256 entries per map and stale suppression entries expire after180 seconds without packets. Skipped audio is not buffered or written to disk. Only real packets received from the modem can go upstream; generated weather remains local.

`end_bulletin` runs in a `finally` block on success or failure. It checks an unpredictable local ownership token and retains a12-second cooldown before releasing new calls. If the caller crashes, a hard840-second lease expires independently; there is no permanent mute or restart loop. A job also retains its180-second maximum waiting deadline, so a very long existing conversation can still cause a report to fail instead of being forcibly cut.

## Validation and deployment

Separate full encode/decode dry runs with network submission stubbed verified release after success and after a simulated playback failure. No RF was generated by these tests.
